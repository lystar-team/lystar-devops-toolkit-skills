# UI Eval Review Rubric

## 适用范围

用于维护 `lystar-ui-design`、验证重复出现的 UI 失败，或比较设计合同是否改变了 Agent 的第一次输出。普通页面开发只做与当前改动直接相关的真实页面验收。

## 固定比较条件

每个 scenario 至少固定：

- prompt；
- 输入数据、文案和资源；
- agent / model / 生成配置；
- 目标视口、主题和需要检查的状态；
- 设计合同或 Skill 版本；
- 第一次输出是否保留，是否允许重试。

Baseline 和 guided 只改变被评估的规则版本或设计上下文；已有 Skill 修订以旧版本为 baseline，不以“完全不加载 Skill”替代。模型、参数、工具、起始代码与其他规则保持一致，使用隔离会话，不让候选版本看到旧版失败与改稿答案。若多份关联规则一起变更，结论只归于该组合。

记录实际加载的 Skill、引用文件与版本，区分未加载、规则缺口与未遵循。生成失败、Harness 失败和业务输入变化单独记录，不能混入设计质量判断。

## 盲评维度

每项使用 `0 / 1 / 2`：

- `0`：缺失、违反要求或产生明显误导。
- `1`：部分满足，需要人工补救。
- `2`：满足当前场景，未发现该维度的已知问题。

### 1. 任务与层级

- 首屏是否让读者知道页面对象、任务和主要动作？
- 主结论或主操作是否与支持它的证据处在合适层级？
- 页面是否围绕当前读者任务组织，而不是套用类别模板？
- 次级任务是否有可发现的入口，并由适合其长度、对象关系与上下文需求的位置承载？
- 多表是否服务同时比较或主从任务，而不是无关管理区堆叠？是否为满足数量或组件名要求损坏流程？

### 2. 事实与文案

- 真实文案、数字、单位、条件、状态和责任主体是否保留？
- 是否把建议、推导或不确定项写成确定事实？
- 是否存在假指标、假品牌、假评价或缺乏来源的承诺？
- 可见段落、字段、Tooltip、空状态与提示是否处于 Contract 允许范围？有无内部实现或调试值越界？
- description 是否有理解或操作用途，必要输入限制、动作后果与可访问性描述是否保留？

### 3. 构图与证据

- 主要关系是否能通过位置、尺度、顺序或对齐快速读出？
- 表格、图表、比较和计算器是否获得与任务匹配的宽度和显著性？
- 是否出现窄表、重复摘要、空洞装饰或同权重堆叠？

### 4. 组件与机制

- 是否沿用了项目已有的字体、token、组件、图标和状态 API？
- 是否出现可复现的任意 spacing、无语义容器、错误控件或主题覆盖？
- 交互、焦点、键盘、加载、空、错误、禁用和长内容是否可达且可理解？
- 页面编排与局部草稿、提交生命周期是否有明确归属？是否因只用一次而合并有职责的组件，或为分层新增无共享需求的抽象？

### 5. 响应式与运行证据

- 目标窄屏是否重排而不是溢出、遮挡或把文字压到不可读？
- light / dark、hover / focus、reduced motion 等要求的状态是否保持层级？
- 浏览器 console、页面错误和可访问性结果是否有单独记录？

## 评审流程

1. 把 baseline 和 guided 的成品证据打乱后评审；涉及交互时查看源码与对应路径证据，不用截图证明操作完成。
2. 记录具体位置、失败类型、用户后果和最小修复，不只写“更好看”或“更专业”。
3. 区分已知失败、主观判断、输入问题和 Harness 问题；不以 description / table 数量、文件行数或指定组件名作硬门禁。
4. 只把能跨场景复现的纠正提升为候选规则。必要帮助、多表对照、长流程与局部修改作为反向检查；不以删除必需功能换取更高分。
5. 对候选规则只运行获准的受影响场景；保留未参与规则调节的 holdout，不把已写进 Skill 的样例当作泛化证据。
6. 人工决定保留、修改、撤回、转成项目 primitive、转成确定性检查，或记录为覆盖缺口。分项记录业务缺陷，不能用视觉分或成本优势抵消。

## 运行记录

```text
Scenario：
Variant：baseline | guided
Prompt / input fingerprint：
Agent / model：
Viewport / theme / state：
Guidance version：
Rendered evidence：
Known failures：
Rubric scores：
Blocking findings：
Reviewer notes：
Decision：keep | revise | revert | no-rule
```

小样本只能说明当前已命名失败是否减少，不能单独证明整体设计质量、可靠性或可发布性。`Guidance version` 记录实际加载文件与版本；`Rendered evidence` 关联源码、截图及本次交互证据；未执行项写入 `Reviewer notes`，不生成通过结果。
