# 结果评审

用于完整页面评审或维护本 Skill 的行为测试。检查实际结果，不用分数、规则数量、截图数量或自评“专业”代替证据；普通局部修改只检查受影响部分。核心方法见 [SKILL.md](../SKILL.md)。

## 三种结果分别成立

| 层面 | 查看什么 | 不可替代它的证据 |
| --- | --- | --- |
| 任务与交互 | 进入原因、对象、状态动作、信息取舍、当前路径与返回恢复 | 页面有全部功能、方案列齐字段、按钮有事件 |
| 内容与视觉 | 实际画面的重点、构图比例、中文排版、密度节奏、材料和细节一致性 | CSS 参数齐全、没有装饰、审美自评 |
| 实现与证据 | 正常数据入口、长内容、目标视口、适用状态和真实运行操作 | 构建通过、静态图、DOM 临时修改或未运行的测试代码 |

三者不能相互抵消。任务错误不能因漂亮通过；交互可用不能证明美观；视觉表达不能证明状态、权限或计算正确。

## 看具体使用过程

### 用户找到并完成任务了吗

- 首屏的对象与入口是否匹配进入原因？哪些内容先看、哪些按需进入，有没有业务或场景依据？
- 高频、紧急与当前待办是否被合理区分？所谓“常用”“推荐”“实时”有没有输入依据？
- 分组对应共同问题还是数据表/组件清单？资料与低频设置是否挤占当前工作？同时比较的数据有没有被错误拆走？
- 状态与动作是否匹配，短编辑取消是否不污染数据，失败是否保留输入，返回是否保留需要的上下文？

### 内容与视觉是否达到当前目标

- 标题与描述是否重复，组件提示是否增添决策信息，帮助是否在需要时可发现？有没有借润色保留无用途文字？
- 对象、位置、时间和状态是否有角色与层级，而不是连续用分隔符拼接？
- 主次是否能通过位置、尺度、对齐、间距与密度读出？重点是否被问候、浅色背景、空洞指标或同权重卡片抢走？
- 排版、比例、留白、颜色关系与组件细节是否协调？配色是否来自项目或一套明确系统，普通文字、状态文字、按钮各状态及当前主题的实际配对是否检查？品牌色、操作底色与其上文字是否分开判断？对比度通过不代替整体视觉判断。
- 有没有核心明确拒绝的装饰型彩色圆角描边/侧边条、渐变强调块、标题徽章、图标盒和重复容器？有必要的输入边界、状态控件和品牌材料不能机械误删。
- 参考确实被查看了吗？迁移的是适用关系，还是组件皮肤、品牌图形、示例数字和无关功能？

### 运行是否支持上述判断

- 长中文、地点、标签、数字与按钮同屏时能否正常显示与操作？既测页面宽度，也测相关子元素与实际遮挡。
- 必须可读的信息有没有被截断后失去获取入口？是否靠裁剪、缩小全页或改 DOM 掩盖溢出？
- 当前平台的返回、键盘/焦点、实际热区、安全区和状态反馈是否可用？console / 页面错误与视觉问题分别记录。
- Web 原型、本地模拟、真实接口和真机检查是否被准确区分？未执行项有没有被写成通过？

## 如何报告

每个问题记录：**位置/状态 → 已观察行为 → 用户后果 → 依据 → 最小修法 → 回查结果**。推断与未复现项单列。核心任务不可完成、事实或状态误导、明显溢出遮挡和明确约束违反不能用其他优点抵消。比例、节奏与审美取舍说明判断理由，不伪造客观分数或确定性门禁。

同时保留少量成立的决定及证据，避免为了凑问题把必要帮助、多表对照、品牌材料或正常圆角控件判错。修正应回到任务、内容、视觉系统或实现责任点，不给失败区域增加补偿性装饰。

## 维护测试的额外记录

保留首次源码、实际加载内容、目标输入与视口、运行证据、发现后的改动和检查成本。维护执行速度时记录开始到首个可查看产物/必要验证完成的耗时、实际读取文件/字节、外部查询和修正；模型、顺序、工具环境不同不能直接归因。局部任务应核对是否读取了无关参考、生图或维护文档。生成者的回读属于自检，不是独立评审；同一智能体连续测试不同任务也不等于独立抽样。负责人应查看成品和证据再采纳结论。

只有明确要求版本对照时才固定其他条件比较旧版与候选版，禁止把“无 Skill”称为旧版。不比较版本就不写提升百分比或因果收益；未运行的固定场景也不是 holdout 通过。少量案例不能证明稳定或资深设计师水准，持续质量仍由不同实际任务的成品验证。
