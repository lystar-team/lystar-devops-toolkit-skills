# 维护边界与责任位置

只在维护本 Skill 时读取。执行方法与明确约束以 [SKILL.md](../SKILL.md) 为唯一入口；本文件不再维护第二份同义规则、逐条采纳状态或历史通过结论。历史场景的实际证据保留在对应 eval 中，不把过去的方案或单次检查升级为能力认证。

## 改在哪里

| 问题 | 责任位置 | 不应采用的替代办法 |
| --- | --- | --- |
| 任务没被理解、功能堆叠、模块优先级失当 | 核心任务与状态、信息取舍和结构决定 | 给每类页面再增加固定模板 |
| 冗余说明、帮助重复、字段关系被字符拼接抹平 | 核心内容准入；具体推演在 design-examples / anti-noise | 累积句式黑名单或改成同义文案 |
| 比例、排版、密度、配色和组件不一致 | 核心视觉方法与项目设计系统 | 把所有页面变成相同主色、纯白或卡片风格 |
| 明确拒绝的视觉表达仍被加入 | 核心中与该决定相邻的约束 | 只放进后置参考，让“有语义”成为豁免 |
| 子元素溢出、草稿污染或状态错误 | 内容/布局边界和实际交互责任点 | 全页缩放、裁剪或新建旁路状态 |
| 检查完成但质量误判 | review-rubric 与真实产物证据 | 扩充自评分项，宣称格式或截图数量证明专业 |
| 平台、资产与参考的专项细节 | 对应平台基线、资产规则、来源记录 | 复制进全部文档或从参考补造业务事实 |

## 维护原则

- 改共同方法与真正断点，先合并重复与冲突，不为一次失败新建独立规则文件。
- 明确的用户要求在适用范围内直接执行，不需要先证明跨场景收益才能尊重；不把局部偏好扩大为所有项目的业务规则或固定皮肤。
- 专业取舍与审美判断允许多种合理答案。只有用户明确且可稳定检查的交付边界、事实和行为错误可作为硬约束；没有依据的次数、尺寸与“一个识别点”不设全局门禁。
- 关键执行约束放在核心决定处；参考承担示例、证据和条件性细节。可选工具或 Skill 不得成为执行核心方法的前提。
- 外部资料证明其内容与来源，不证明本 Skill 的产出质量。保持真实素材与来源记录，删除无当前职责的重复治理，不改写历史测试成已通过。
- 指令版本、工具环境与实际读取内容分开记录。修订后核对格式、引用、安装内容和获准的行为测试，不以文件相同证明设计质量。

## 旧记录如何理解

既有场景或报告可能保留 `ui/core/...`、`ui/content/...`、`ui/composition/...` 等 ID，以及 baseline/guided、分数或 proposed 字段。这些属于当次记录，不是当前执行接口和采纳状态。审阅其输入、实际运行和限制后再作判断，不根据旧 ID 推导新的硬规则。
