# 国内产品与平台基线

用于中国后台、企业 App、微信小程序和中文内容的实际适配。核心设计方法见 [SKILL.md](../SKILL.md)；这里补平台与内容约束，不用市场名称规定统一皮肤、字号或组件库。

## PC 后台与连续操作

先确认用户是查询、分派、审批、核对还是维护资料。对象、状态、判断字段和动作获得稳定位置；筛选跟随结果，批量操作仅在真实任务和接口支持时出现。低频档案和设置保留入口，不因为数据存在就常驻工作台。

复杂中文、组织名、日期、金额、单位与业务编号进入真实列表和表单。为扫描与比较分配宽度，对齐数字和重复字段；紧凑密度不等于压小文字或把长字段全截断。主从、详情页和弹窗根据持续处理与上下文需要选择，不能只按组件名字选布局。

左侧导航、状态筛选和操作列是可选的熟悉模式，不是必须齐全的框架。项目已有结构与 API 优先，借鉴 Ant、Arco 等不授权换库、造指标或加入未要求的导出和权限管理。

## App 与微信小程序

从移动场景的进入原因、当前对象与下一步出发，按此重排首屏和路径。不把 PC 菜单缩成宫格，也不把所有资料做成长列表塞进首页。新建、已有记录和需要本人处理的事项各有入口与优先级依据。

沿用真实平台的导航、返回、底部栏、安全区、键盘和授权行为；没有需求不添加登录或分享。微信胶囊属于平台表达，不是可移植的品牌装饰。使用当前平台资料或项目代码确认尺寸与机制，不从设计展示图推导 CSS / rpx。

目标手机尺寸下检查实际可点区域、按钮文字、长位置和固定操作区。输入过程中键盘不应挡住当前字段或完成动作。窄屏按任务重排、展开或局部滚动，保留关键信息；需要比较时提供可理解的对照路径，不靠缩放桌面画布。

加载、提交、失败、空记录和返回只覆盖本次适用状态，慢请求时让用户知道当前结果且不重复提交，失败保留输入。已有登录、权限、草稿和网络机制直接复用，不为“平台完整”追加任务外能力。

## 中文内容与视觉表达

- 中文的字面、字重、行高、行宽与混排共同校准，不把英文字号直接当中文答案。使用真实标题、正文、数字、日期与单位查看基线、换行和密度。
- 对象、位置、时间与状态有不同角色，用结构与文字表达；不要以大量 `·` 拼出辅助信息，也不要用装饰英文替代中文任务。
- 阅读页按实际内容建立标题层级、段落节奏、目录和图表空间；技术材料保留必要代码和术语，不能把用户需要的技术信息误删为内部实现。
- 品牌页与内容页可以有图像、字形、材料与主题，不要求后台密度；后台和服务页也不以浅色 Hero、渐变和运营卡片证明国内适配。
- 色彩、几何与表面遵守项目系统和核心边界；国内产品不等于蓝色、绿色、高密度或彩色状态胶囊。

## 参考与验证

先使用项目事实、既有合格页面与设计系统，再按当前问题选择 [图文参考](reference-map.md)。组件参考解决控制与状态，成品参考提供可见比例和关系；它们都不是本项目业务证据。国际或国内品牌案例均须判断场景与材料适用性，不能仅因地域、获奖或作者评价就迁移。

验证记录区分 Web 原型、开发工具、真实接口与真机运行。没有真机证据时，不说小程序在微信上已通过；有运行截图时，仍需核对返回、提交和恢复，而不是只证明画面能显示。
