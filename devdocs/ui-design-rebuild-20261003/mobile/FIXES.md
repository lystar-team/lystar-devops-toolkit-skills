# 移动端原型修正记录

首版（first/）在冒烟检查中未发现阻断缺陷；如后续测试发现问题，修正记录追加于此，first/ 不被覆盖。

## F-M01（首次测试后定点修正）
- 现象：底部确认面板打开后键盘焦点仍停留在背后的触发按钮；Escape 不关闭面板；Tab 会离开面板进入背景内容。证据：evidence/mobile/interaction-log.md 的 M10（activeElement="取消预约"，afterEscapeSheetHidden=false）。
- 修法：打开面板时聚焦主按钮；关闭时焦点回到触发元素；Escape 关闭；Tab/Shift+Tab 在两个面板按钮间循环；成功提交后焦点转到成功提示（预约）或页面主区域（取消）。影响文件：mobile/app.js、mobile/styles.css（.screen:focus）。
- 回查：M10b 焦点序列与新流程回归。

## F-M02（定点复测轮，暴露问题后）
- 位置：移动端书目详情（存在本人 ready 预约的书目，如 B02；B01 预约成功后同样进入该状态）
- 观察（父会话复核暴露）：被自己的待取预约挡住时，详情仍显示新建预约的通用期限“预约提交后两天内，当日 18:00 前”，并且没有通往该关联预约的入口。
- 用户后果：用户看不到自己实际需要取书的期限，也不知道去哪里查看或取消已有预约；新建流程的通用说明挤掉了当前记录的真实信息。
- 依据：已安装 SKILL 第 1 节新增段落（“有关联的已有记录……在该对象上下文提供相应入口；不让用户退出后重新查找”“涉及期限、资格或结果时读取当前记录，不能套新建流程的通用说明”）；父会话复核输入见 parent-review/；复测记录见 evidence/followup/interaction-log.md。
- 修法：详情中存在本人 ready 预约时，取书期限读取该记录的 pickupUntil 并格式化；notice 内增加“查看该预约”入口，跳转我的预约；available=0 且无本人记录时不显示入口，保留原有提示。影响文件：mobile/app.js、mobile/styles.css（.notice-link）。
- 回查：T1/T1b 显示实际期限与入口，入口进入我的预约并显示对应卡片；T2 预约 B01 后进入同一状态；T3 无入口；T4 仍可约；T6 在 360 宽无溢出；T5 B02 详情 axe 0 violations。
