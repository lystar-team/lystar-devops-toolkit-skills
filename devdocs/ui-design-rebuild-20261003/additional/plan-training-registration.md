# 企业培训报名长流程 · 设计决定（只出方案）

范围：给出结构、状态与视觉决定，不实现。不设计自动保存；阶段保存、持久化与返回继续的现有机制以项目实际依据为准（待确认），不能因为流程需要就声称系统已有。培训名称与资格来自接口；表单已有独立编辑路由，本方案不新建第二套编辑器。

## 任务与边界

- 使用者：需要报名企业培训的员工。进入原因：选择课程、确认自己是否符合资格、补充附件、由负责人确认后提交。
- 需要得到的结果：一次可提交、可中途离开再回来继续的报名。
- 已有事实：课程名称与资格数据来自接口；项目已有独立编辑路由；流程分阶段。
- 保存能力待确认（项目依据）：该编辑路由当前是否支持按阶段保存、服务端是否保留已保存阶段、用户重新进入（刷新、换设备或从工作台返回）后恢复到什么状态。确认前，本方案关于保存与恢复的行为都只是方案判断。
- 本次不做：不设计自动保存、草稿定时落盘、消息通知、审批时限规则、支付费用；“不设计自动保存”是本次设计边界，不代表系统现状或未来能力。
- 待接口确认：资格规则字段、附件允许的格式与大小上限、负责人来源与确认方式、可提交的前置条件。这些未确认前不写死常量。

## 结构与路径

| 区域 | 服务的用户问题 | 默认信息与当前动作 | 按需进入 |
| --- | --- | --- | --- |
| 报名工作台（阶段导航） | 我进行到哪一步、下一步是什么 | 培训名称、当前阶段、各阶段状态、继续按钮；已完成阶段可回看 | 不展开各阶段表单内容 |
| 阶段一 选择课程 | 报哪门课 | 课程列表或当前已选课程；选择后进入资格核验 | 课程详情按需查看 |
| 阶段二 资格核验 | 我能不能报 | 核验结果：符合 / 不符合（原因）/ 待核验（进行中、失败可重试）；不符合时说明原因与可做动作 | 资格规则的完整说明按需展开 |
| 阶段三 填写与附件 | 还缺什么材料 | 表单字段按业务必填顺序；附件区在上传位置表达格式与大小限制及数量 | 已上传文件可预览或删除 |
| 阶段四 负责人确认 | 谁确认、确认到哪一步 | 负责人、当前确认状态（待提交确认 / 待确认 / 已确认 / 被退回及原因） | 退回后回到相应阶段修改并重新提交确认 |
| 阶段五 最终提交 | 是否可以提交 | 提交前汇总：课程、报名信息、附件、确认结果；提交按钮仅在前置条件满足时可用 | 提交后进入结果页或记录详情 |

路径：进入 → 工作台识别当前阶段 → 完成当前阶段并显式保存 → 返回工作台或直接进入下一阶段 → 全部满足后提交 → 结果与新记录入口。

- 阶段表单使用已有编辑路由，不改造成多步弹窗。本方案按“显式保存”设计（方案判断，待项目确认）：每一阶段的保存是显式动作，保存成功后才更新阶段状态；若现有编辑路由已具备阶段保存或草稿机制，则沿用其行为，不新增第二套保存。
- 中途离开：工作台展示的项目阶段状态取决于已确认的保存机制。在确认前，本方案按“未保存的表单输入离开即丢弃”设计，并在取消时明确说明该后果；若项目已有恢复机制，按项目现状执行并修正提示。
- 被退回：确认阶段展示退回原因，用户回到对应阶段修改，重新提交确认；退回后保留的内容范围同样以已确认的保存机制为准。

## 状态

- 加载 / 空 / 接口失败：课程与资格来自接口，单独给出加载、空结果和失败重试；失败不丢已选内容。
- 资格：符合、不符合（原因）、待核验、核验失败可重试。
- 附件：待上传、上传中、失败（保留已选文件并可重试或删除）、已上传；格式或大小不符时指出具体文件与原因。
- 确认：待提交确认、待确认、已确认、被退回（原因）。
- 提交：可提交、提交中（阻止重复）、失败（保留全部已保存内容并可重试）、成功（显示提交结果与记录入口）。
- 全程只有一个进行中的提交动作；按钮与阶段状态一致，不用静态成功图代替。

## 视觉决定

- 默认重点：培训名称与当前阶段；阶段导航用文字与进度位置表达，不为每个阶段加彩色徽章或侧边条。
- 表单区宽度按输入与阅读需要限制（约 720–880px），长培训名称与机构名称允许换行，不截断关键信息。
- 阶段导航与表单使用项目既有组件与 token；状态用文字加项目现有状态样式，不新增品牌色。
- 附件限制（格式、大小、数量）写在附件输入处；错误说明问题与恢复动作。
- 手机上按动作顺序单列，阶段导航折叠为当前位置与返回入口，操作区避开键盘与安全区。
- 提交前汇总使用只读信息区，不用营销式图表或指标卡补足篇幅。

## 结果与验证（实施时）

- 交付入口：工作台路由、既有编辑路由的阶段参数、各状态截图与交互记录。
- 验证点（在保存/恢复机制获得项目确认后执行）：阶段保存后状态更新；离开再继续能看到实际保留的阶段；取消不产生保存；资格不符合与退回路径可走通；附件越界提示准确；提交失败保留、重试只提交一次；手机与桌面目标视口下长中文不溢出。
- 未确认项（项目与接口）：阶段保存与恢复机制、资格规则、附件上下限、负责人确认机制、提交前置条件。实施前需用真实机制与接口字段替换本方案的方案判断，不得自行写入规则。
