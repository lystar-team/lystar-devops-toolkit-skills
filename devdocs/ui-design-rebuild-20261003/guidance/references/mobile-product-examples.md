# App 与小程序产品案例

本轮补充四组、七张原始画面，核验于 2026-10-03。读取相关说明和原图后再作设计决定。App 画面来自 UI Notes 公开截图库，小程序画面来自设计方发布的项目案例；均未进行客户端或真机操作。来源、原图地址与尺寸见 [来源记录](examples/sources.json)，浏览入口见 [图文浏览页](examples/index.html)。

这些案例分别补充内容发现、品牌阅读、会员服务和购买流程。原有 Ant / Arco 用于后台组织，TDesign / WeUI 用于组件与状态。本轮案例提供移动成品和项目设计的可见依据；每项判断只覆盖明确说明的优点。

| 当前任务 | 案例 | 主要观察 |
| --- | --- | --- |
| 内容型 App 的发现与持续消费 | `cn-xiaoyuzhou-discovery` | 内容层级、单条动作、常驻播放条与底部导航 |

| 消费端小程序的会员与权益 | `cn-yili-member` | 高频服务分组、品牌图形、权益状态与详情展开 |
| 中国市场的小程序购物 | `cn-hublot-wechat` | 展示、选品、购物袋与结账的视觉密度变化 |

## `cn-xiaoyuzhou-discovery`：内容与播放保持各自位置

![小宇宙的内容发现与入口引导](examples/mobile/podcast-categories.webp)

![小宇宙的编辑精选和常驻播放条](examples/mobile/podcast-discovery.webp)

**来源**：UI Notes 的小宇宙 App 截图 020、023。已打开各截图详情并下载、查看原图；每张为 1170 × 2532 图像像素。截图属于图库保存的版本，不能称为当前最新版。

**可见观察**：封面识别节目，节目名建立上下文，较重的单集标题承担主要信息；播放按钮靠近对应单集。分类入口、推荐内容和底部播放条具有不同角色，播放条与底部导航的位置在两张画面中保持一致。浅蓝用于内容入口、播放及识别图形，不把每条记录做成大面积彩色卡片。

**设计理由与迁移**：内容 App 可以让浏览新内容和控制当前内容并存。复用同一封面、标题、摘要和主动作的关系；在项目已具备持续播放或持续任务时，考虑保持局部控制入口。分类引导直接指向相关入口，避免解释整个页面。

**边界**：蓝色、星球图形、朋友推荐和播放能力属于这个产品。浅灰辅助文字的对比度没有实测，不能直接继承其颜色。两张静态图只显示播放条位置一致，没有验证播放是否连续、引导能否关闭或导航返回状态。图像像素不提供 CSS 字号或触控尺寸。

## `cn-heytea-brand`：同一品牌的首页与阅读节奏

![喜茶 GO 的品牌首页与取餐方式入口](examples/mobile/heytea-home.webp)

![喜茶 GO 的手机品牌长内容](examples/mobile/heytea-story.webp)

**来源**：UI Notes 的喜茶 GO App 截图 011、030。已打开详情并查看原图，每张为 1170 × 2532 图像像素。这里研究 App 的首页与品牌内容，未把它归为微信小程序或点餐流程实测。

**可见观察**：首页让产品照片与手绘中文标题成为主体，到店取和外送入口靠近当前产品，下方保留导航。长内容采用暖色纸张、照片组合和中文段落，阅读区保留返回入口。首页的大图留白与内容页的纵向节奏分别服务展示和阅读。

**设计理由与迁移**：品牌识别可以来自材料、照片、字形和编辑方式，不只来自主色。用真实品牌材料建立识别，再让动作获得清楚位置。内容页按章节、图像和段落安排阅读；商业主操作与长篇阅读可以采用不同密度。

**边界**：手绘大字属于展示内容，不替代正文、字段或错误帮助。纸张和照片叠放需要品牌与内容依据；查询表格、审批和快速填报仍以操作为主。图中留白、静态取餐按钮和返回图标不证明点餐、外送或返回位置已经验证。

## `cn-yili-member`：品牌表达与服务分组

![活力伊利的购买入口、品牌馆和奶卡展示](examples/mobile/yili-details.jpg)

![活力伊利的个人服务与会员权益展示](examples/mobile/yili-activity.jpg)

**来源**：维好维可发布的“活力伊利小程序全流程UIUX设计”案例，两张项目展示图均为 3840 × 2400 图像像素。已读取设计方正文并查看原始画面。它们是设计交付展示图，不是本机小程序截图；上线状态与效果未独立确认。

**可见观察**：买牛奶、订奶卡是较大的功能入口；签到、抽奖等放在次级操作组。个人页按订单、奶卡、互动分组，会员详情再展开权益及对应动作。产品摄影、品牌标志、奶牛形象和不同权益图标形成同一视觉语言。卡片分隔服务集合，彩色图形承担品牌与类别识别。

**设计理由与迁移**：会员产品先安排常用服务与当前权益，再展开成长规则。品牌可以使用有意义的图形和材质；动作、状态与分组仍须清楚。已有明确会员机制时，保留已领取、可领取与未解锁的文字区别；数量和按钮由真实数据决定。

**边界与发现**：展示图中 V3、1780 成长值、2000 刻度和“再70成长值”的示例不一致，不作为等级计算或数值状态正例。促销、抽奖、积分和权益不迁移为项目默认能力。首页运营信息较多，当前任务以快速办理为主时应调整优先级。这里只借鉴所述层级、图形和分组。

## `cn-hublot-wechat`：展示与结账使用不同密度

![宇舶在华微信小程序的展示、选品、购物袋与结账](examples/mobile/hublot-flow.jpg)

**来源**：Digital Creative Asia 发布的宇舶中国微信电商案例。原始多屏图为 2200 × 1505 图像像素，能看到微信胶囊导航、中文字段、购物袋和结账。设计方说明项目始于 2020 年；不称为现版界面。宇舶是国际品牌，本例的适用环境是中国市场和微信平台。

**可见观察**：商品展示使用较大图像与黑色背景，详情、购物袋和结账改用白色工作面；红色表达选择与动作。价格、规格和当前动作靠近商品；结账按配送、地址、发票、商品与费用分组。品牌表达强度随任务变化，支付前的信息变得更明确。

**设计理由与迁移**：同一品牌不必让所有页面保持相同展示密度。发现与展示突出对象，比较与结账突出差异和所需输入。采用项目已有的商品摘要和状态机制，在微信导航与页面动作之间保留各自位置。

**边界**：黑色、红色、腕表照片和大图适用于此品牌；不推广为企业系统默认样式。购物袋与结账图里的商品组合不同，不能当作同一订单金额一致性的证据。订金、银行转账、客服和礼物选项属于该项目；静态图没有验证实际购买、取消、失败或微信授权。

## 补充参考的选择方式

先按任务找产品或项目，再观察相关多屏画面。站酷、UI 中国用于发现作者与完整项目；UI Notes 用于观察产品截图；设计团队和设计公司原站用于核对项目说明。关注中文内容的层级、图像与文字比例、页面之间的关系和状态。只选封面或样机时，证据范围停在可见构图。

App 与小程序任务同时考虑视觉品质与平台操作：不能只看组件是否齐全，也不能凭好看的品牌展示推导完整流程。项目记录说明本次怎样采用参考、怎样调整，以及哪些动作仍需运行验证。
