# 内容与视觉校准

在结构草案、视觉选择和运行回读时使用。核心边界已经在 [SKILL.md](../SKILL.md)，本文件补充怎样识别问题，不是必须最后才加载的另一套规则，也不授权扩大修改范围。

## 先判断内容是否取得展示资格

可见内容应承担辨认对象、判断状态、选择、输入、行动、反馈或恢复中的具体职责。先删无职责内容，再润色；组件提供 description / helper / subtitle 插槽不是使用理由。

| 常见输出 | 问题 | 应怎样处理 |
| --- | --- | --- |
| “报修管理”下再写“在这里管理所有报修” | 没有新增决策信息 | 留标题与实际操作，不换一句同义介绍 |
| 发起按钮下写“选择设备、填写描述、提交报修” | 重复后续界面可直接表达的步骤 | 把真实要求落实到表单对应字段，不在入口讲解流程 |
| 上传标题已显示数量上限，下面再写同一上限 | 同一操作上下文重复 | 以用户输入时最易发现的位置表达；保留具体错误和恢复帮助 |
| 名称、位置、时间、状态全部用 `·` 串起来 | 不同信息角色被字符串抹平，长内容挤压动作 | 分配对象标题、字段标签、辅助信息和状态的位置；实际名称中的符号不改 |
| 把全部资产叫“常用设备”、给静态数据标“实时” | 假设被写成事实 | 按数据实际含义命名；没有频率或更新依据就不作这种承诺 |

必要帮助不是噪声。比如格式限制、不可逆后果、当前资格或错误恢复会影响操作时应保留，放在用户需要它的位置。避免为了极简删掉完成任务所必需的条件。

## 再判断视觉是否解决了结构问题

- 用户首先注意到的对象和动作是否与任务一致？大标题、强底色或问候不能默认获得首屏重点。
- 内容密度是否适合扫描、比较或阅读？更大的留白并不自动更专业，紧凑也不等于小字堆满。
- 字体角色、对齐、行高、组内与组间距是否已经表达关系？边框、背景、阴影与圆角不应重复包裹同一关系。
- 颜色是否协调且有强弱？主色不是全页滤镜，状态色不让每条记录成为彩色胶囊。把装饰命名为“品牌”或“状态”不能替代必要性判断，更不能绕过用户的明确边界。
- 卡片是否对应对象、真实分组或独立交互？若每个字段都要一个容器，应回到结构，而不是再统一容器颜色。
- 图像、材质与动效是否有内容用途？保留真实品牌表达与必要反馈，不用展示型风格包装普通操作页。

**明确拒绝的装饰模式按核心执行，不做“有语义”豁免。**必要的输入边界、控件错误/焦点、平台胶囊和项目组件有自身职责，不能因为都带边框或圆角而机械删除。

## 在画面里验证，不只解释 CSS

在真实显示尺寸看首屏与滚动后的信息：重点能否被找到，次级内容是否挤占空间，颜色撤掉后层级是否仍然成立。然后检查长中文与操作并存时的换行、截断、热区和边界。页面无横向滚动，只证明页面边界；子元素仍可能溢出或被裁掉。

发现重点错误先调整信息和尺度；发现冗余先删除重复内容；发现溢出按内容角色调整布局。不能靠补一条提示、再套一层卡片、统一缩小文字或 `overflow:hidden` 掩盖问题。最终仍须校准比例、排版和细节，美观不是单纯删除元素后的空白。
