# 国内 UI/UX 图文正例

用于新建页面或结构调整。先按任务选一个案例，读取文字与对应原图；只查看品牌名或缩略图不算完成参考研究。局部修改优先项目原页面。

参考库现有十组、十五张画面。其中原六组于 2026-10-02 核验，补充的四组 App / 小程序产品案例于 2026-10-03 核验。它们是具体结构、视觉或状态的参考，不代表整套产品都优秀，也尚未经过 Yean 的审美确认。浏览入口：[图文浏览页](examples/index.html)。原始地址、证据类型和尺寸见 [来源记录](examples/sources.json)。

先按任务而非平台选参考：输入、记录与状态可用下面的控件和流程依据；内容发现、品牌阅读、会员服务与购物可按适用条件读取 [移动产品案例](mobile-product-examples.md)。同为 App 或小程序不代表结构与品牌表达可以互换，使用时以 [参考入口](reference-map.md) 的当前设计问题为准。

## `cn-ant-query`：查询与选择后的批量操作

![Ant Design Pro 查询表格](examples/ant-query.png)

![选择一行后的批量操作](examples/ant-selection.png)

**证据**：实际打开官方预览，在 1440 × 1000 视口捕获默认列表，再点击第一行复选框捕获选择态。DOM 同时显示一行选中与“已选择 1 项”。

**值得学**：筛选负责缩小范围，表格负责比较，行内入口处理单条；选择后才出现批量操作。状态采用文字加色点，行结构保持对齐。用户不必从装饰摘要里重新寻找当前任务。

**实测与迁移**：当前预览表格正文 14 CSS px、行高 47 CSS px、主按钮高 32 CSS px。它们是这个版本的测量值；目标项目以既有 token 为准，长供应商名称或附件数量可能需要更高行高。先固定对象、状态和行操作列，再调整辅助字段。

**限制**：演示的 TradeCode、1970 年日期、随机调用次数不是业务资料。页面重复标题、左下装饰背景、配置浮钮和重复选择摘要不作为推荐项。选择态的截图不证明批量审批业务已实现；不能把演示按钮迁移为项目权限或审批规则。

## `cn-arco-query`：多条件筛选与连续扫描

![Arco Pro 查询表格](examples/arco-query.png)

**证据**：实际打开官方 Vue 预览的查询表格，在 1440 × 1000 视口捕获，并读取 DOM 尺寸。

**值得学**：六项筛选组织为两行网格，查询与重置位于共同操作列；筛选下方分隔线连接列表工具栏与结果。字段名、值和动作各有稳定位置，表格正文没有逐行卡片化。分区由对齐、间距和细分隔线表达。

**实测与迁移**：正文 14 CSS px、数据行 43 CSS px、主按钮高 32 CSS px。与 Ant 的 47 px 行高对照，说明“紧凑”需要具体参数及内容依据，不能成为统一数值。保留项目既有标签宽度，按真实字段长度决定筛选列数。

**限制**：截图中的英文枚举、随机名称、1988 年日期和数字前导零不进入业务成品。没有实测其所有工具按钮、权限或窄屏路径。这里只借鉴筛选与结果的组织方式，不迁移整套导航或更换组件库。

## `cn-feishu-approval`：企业审批入口的跨端组织

![飞书公开展示的桌面与手机审批入口](examples/feishu-approval.webp)

**证据**：飞书审批官方产品页公开的产品界面展示图；已下载原资产并查看。它包含桌面与手机界面，不是本机登录客户端后的截图，也不能证明点击、授权或性能表现。

**值得学**：搜索、分类和常用申请解决不同的找入口路径；桌面利用多列分类，手机将常用入口压成网格、其余分类改为纵向列表，保留底部导航。入口图标具有类别含义，卡片具有可点击功能集合的边界，不能因“图标盒/卡片”外形就删除。

**迁移**：先统计真实功能数量、使用频率和名称长度，再选网格或列表。高频入口可提前，低频项目保留分类和搜索；手机按任务重排。采购审批队列应使用记录列表，不因这个案例存在网格就改成入口宫格。

**限制**：官方资产带设备框与展示阴影，它们不进入实际工作台。分类、数量、图标、导航和审批能力属于飞书，不是当前项目事实。该图只能支持可见布局判断，不支持最新客户端全部状态或跨端行为结论。

## `cn-tdesign-publish`：输入流程与草稿/发布

![TDesign 小程序发布页面](examples/tdesign-publish.png)

**证据**：TDesign 团队通用小程序模板 README 引用的官方截图，750 × 1624 像素。该尺寸是图像像素，不能直接当 CSS px 或 rpx。

**值得学**：图片、描述、标签、位置依输入顺序组织；文字输入获得主要空间。底部将“存草稿”和“发布”置于同一操作区，通过权重区分结果。删除入口附着于对应图片，用户无需到另一处管理附件。

**迁移**：报修或巡检表单按业务必填顺序排列；保留输入增长空间，长名称允许换行，主操作区避开安全区与键盘。只有需求已有草稿能力时才提供存草稿；发布失败后保留输入。

**限制**：动态发布的标签、地理位置、500 字限制和图片上限不是巡检或报修的默认要求。静态截图没有证明上传、离线、键盘和授权路径可用；小程序验收需要开发工具或真机，不用浏览器截图冒充。

## `cn-tdesign-order`：状态列表与详情的信息展开

![TDesign 小程序订单列表](examples/tdesign-orders.png)

![同一订单的完整详情](examples/tdesign-order-detail.png)

**证据**：腾讯零售模板仓库 README 的官方订单与详情截图，分别为 437 × 914 像素。列表和详情包含相同订单编号与 0.20 元示例实付金额。

**值得学**：列表用状态页签缩小队列，每条记录保留对象、金额、状态和当前可做动作；详情展开地址、费用组成、编号与时间，不把所有内容常驻列表。金额、小计与实付各有角色；复制入口紧邻编号。卡片边界对应订单对象，红色对应这套零售主题与待付款动作。

**迁移**：设备任务、报修与业务单据保留“对象摘要 → 状态 → 主动作”，进入详情再展开材料和记录。列表返回后保留筛选和位置；多个动作按单据状态决定，不能全部堆在底部。

**限制**：模板使用模拟数据。商品金额、优惠、支付时限、业务按钮、红色主题和地址都不是企业审批或社区报修的规则。图中其他订单的费用汇总未独立核对，不作为计算正例。只借鉴已说明的层级与列表/详情关系。

## `cn-weui-upload`：状态留在上传对象上

![WeUI 上传组件的进度、错误与删除态](examples/weui-upload.png)

**证据**：实际打开 WeUI 官方 Web 演示，在 390 × 844 视口捕获；属于上传状态示例，不是实际上传服务或完整微信小程序。

**值得学**：上传中进度、错误标记和删除动作都留在对应缩略图位置；用户能辨认受影响的附件。新增入口与已选图片共同组成可扫描区域，图片管理不需要多层弹窗。

**迁移**：附件有独立状态，失败时保留缩略图并提供重试或删除；数量以真实上传限制和已选文件计算。触控热区、删除的可访问名称和键盘反馈按项目组件实现。

**限制**：演示同时放出多种状态，3/10 是示例标签，不用它校验实际文件计数。标题英文、占位图片、底部版权页脚和演示数量不作为中文成品正例。截图不证明上传端点、失败恢复或屏幕阅读器可用。

## 参考转成决定

只记录本次有用的 1—3 项：

```text
参考与证据类型：案例 ID / 原图 / 版本或捕获日期。
可见观察：哪种位置、比例、参数、状态或对象关系实际出现。
选择理由：它怎样帮助本次用户任务；哪些部分不适用。
实现映射：项目组件与 token；需要调整的字段与目标视口。
验证：实际内容、交互和状态怎样检查。
```

优先读取项目已有合格页面。公开参考需要时，用 agent-browser 查询官方页面，用 agent-reach 查询 X / GitHub；读取后保存本次需要的实际画面。参考不可访问时沿用已核验画面并标出日期，不能编造观察。

## 本轮未选为现版视觉正例的材料

- 企业微信旧员工手册中的审批画面：可说明历史操作分组，不能代表当前版本的视觉品质。
- WeUI 表单结构整屏：含英文标签断裂，只能研究局部分组，不作为完整中文表单样板。
- 飞书多维表格宣传拼图：突出展示效果、设备透视与图表种类，不能据此给操作页添加图表或指标。

判断“好”应落在具体任务、内容层级、参数和状态；来源可靠不等于整屏适合照搬。Yean 后续认可或否定某个方向时，在相应案例记录适用范围，不升级成所有页面的固定皮肤。
