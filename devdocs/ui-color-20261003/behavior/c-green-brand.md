# C · 保留给定亮绿品牌，处理14px白字按钮的配对

本项由负责人在测试会话接口中断后接手，是对安装后0.5.1方法的定点执行，不是第二个独立测试智能体的结果。只给方案，不实现第二个业务页面。

输入：微信服务语境；品牌 `#07c160` 不可改；需要14px主按钮白字。没有给定已有组件主题，不新增框架依赖。

使用已安装的 `scripts/color_tools.py` 计算实际颜色对：

| 颜色对 | 对比度 | 判断 |
| --- | --- | --- |
| 白字 / `#07c160` | 2.3848:1 | 不满足普通文字4.5:1 |
| 白字 / 本地适配操作色 `#007d3d` | 5.2489:1 | 满足普通文字门槛 |
| 黑字 / `#07c160` | 8.8059:1 | 若允许深色文字且按钮底锁定亮绿，可采用 |

本次推荐：品牌仍是 `#07c160`，主操作底色映射到同绿系的本地适配 `action`，按钮文字保留白色；hover/active用该基线的对应角色并逐一核对。不能把品牌值改写为深绿，也不能把这些适配值称为WeUI官方完整主题。若项目本来已有WeUI，则在共同主题/组件责任点处理实际配对，不套入第二套CSS。

如额外要求按钮底也必须精确为 `#07c160`，同时保持14px白字，这些条件与4.5:1门槛冲突，应明确取舍；不能以它来自大厂为由写成通过，也不能擅自缩小门槛。大字豁免不适用于14px。

计算输出见 `../evidence/c-brand-green-pairs.json`。方案未运行微信、未连接接口；负责人另建的基线验证页可查看绿色实际视觉，但不等于本项业务页或真机通过。
