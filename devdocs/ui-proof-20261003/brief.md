# 双端 UI 设计测试：园里报修

## 目标与输入

Yean 要求用当前安装的 `lystar-ui-design` 产出一套 PC 后台和微信小程序 UI，查看实际设计效果。题目为本次设定的园区设备报修业务，不是客户真实项目。所有姓名、设备、记录、时间和照片都是演示材料。

品牌：园里；服务地点：青禾创智园。给定品牌主色为 #177568。无现成设计稿和组件规范，由设计执行者根据任务自行选择布局、密度、排版、组件参数与参考。不能把演示当成正式维修服务。

## 使用者与任务

- PC：园区服务中心的调度人员。在队列中找到需要处理的报修，查看完整材料，选择维修人员并派单，跟踪处理结果；取消编辑不应改变记录。设备和人员资料支持派单判断。
- 微信小程序：园区员工陈予安。快速选择设备和位置，描述故障并附图；提交后查看进度，维修完成后确认结果；返回列表保留上下文。

## 数据与业务范围

共享事实源为 `shared/store.js`。每端使用同一记录及状态定义，状态依次为待派单、已派单、维修中、待确认、已完成。派单只从待派单进入已派单；后台可记录已派单/维修中的处理结果，进入待确认；员工确认后进入已完成。

报修至少包含设备、类别、故障描述、联系人和手机。描述最多300字，最多3张图片。演示使用本地持久化与延迟模拟提交。图片为本地预览，不上传服务器。提供正常、必填、提交中、失败保留、成功和空查询状态；失败模拟只放在设计体验入口，不混入正常产品操作。

给定数据覆盖长设备名、长中文描述、多地点、多类别、不同优先级与状态。数量从记录计算，不编造统计指标。设备/人员是只读资料，不扩展资产编辑、考勤、费用或权限管理。

## 交付

- `pc/`：可运行的报修工作台、详情与派单、设备和人员资料。目标桌面1440×1000。
- `mini/`：微信导航语境的浏览器交互原型，包含首页、我的报修、报修表单、进度详情、提交成功。目标390×844。不是原生小程序，不宣称微信开发工具或真机验收。
- 两端均仅使用 HTML/CSS/JavaScript 和本地资产，可通过静态服务器打开。没有构建依赖、远程字体或 CDN。
- 执行者自行读取 Skill 相关说明及原图，留下简短参考观察、设计参数和实现映射。保留首次输出，再对真实发现的问题作局部修正。父会话不提前指定参考答案或完整布局。
- 展示入口提供双端原型和页面截图，标明设计测试/示例数据。截图来自运行页面，不用生成效果图冒充已实现页面。

## 共享 API

通过 `<script src="../shared/store.js"></script>` 读取 `window.Park`。接口定义以该文件为准。图标使用 `shared/icons.js` 的 `window.Icon(name,size=20)` 返回内联 Lucide SVG。运行素材目录为 `../assets/`。
